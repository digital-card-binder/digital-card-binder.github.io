## 10차: 검색 성능
- 통합검색에서 검색 결과 2만 장을 한꺼번에 카드 DOM/이미지로 그리지 않고, 처음 60장만 렌더한 뒤 60장씩 추가합니다.
- **검색 결과 총 장수는 유지**하며, 필터·검색어 변경 시 첫 60장으로 복귀합니다.
- 한 번 더 보기는 현재 카드 DOM을 보존하고 다음 카드만 추가합니다. 카드 데이터/보유 상태는 변형하지 않습니다.
- 회귀: 20,000장 가상 검색, 143장 마지막 구간, 12장 소규모 결과 및 필터 초기화.

## 11차: 백업/복구 안전성
- 운영센터 `operations.html` → 관리자 계정 → `백업 파일 만들기`.
- 백업에 쓰이는 Firestore **문서/바인더/이미지 조각은 서버 읽기만 사용**합니다. 네트워크 오류 시 오래된 로컬 캐시에서 묵시적으로 백업하지 않고 실패합니다.
- 신규 백업은 `accountUid`를 포함하며, 현재 로그인 계정과 다른 계정의 복구 요청을 거부합니다. **계정 정보가 없는 이전 백업은 경고 후 기존 호환성을 유지**합니다.
- 파일을 선택할 때 JSON·스키마·바인더 이미지 조각 및 반영 가능한 쓰기 용량을 검증한 뒤에만 복구 버튼을 활성화합니다.
- **실제 로그인 사용자 Firestore 기록을 임의로 다운로드·복원하지 않습니다.** 운영자가 백업 파일을 로컬로 안전하게 보관해야 합니다.
- 복구는 파괴적일 수 있습니다. 현재 상태 백업 → 파일 점검 → 영향 범위 확인 → 수동 동의 → 복구, 순서로 진행합니다.
