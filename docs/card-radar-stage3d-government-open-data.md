# 카드 레이더 Stage 3D — 정부 공공 상가 위치 API (선택 연동)

## 목적

현재 자체 Firebase `digital-card-radar-db`의 검증 매장 수는 1곳. 오픈소스 상용점포 스크래핑 대신 **정부 공식 공공데이터포털**의 전국 상가업소 API를 선택형 점포 *후보* 수집원으로 추가한다. 지점명/좌표 확보 이후에도 포켓몬 카드 재고는 여전히 `unknown` 상태다.

- 데이터셋: https://www.data.go.kr/data/15012005/openapi.do
- 제공: 소상공인시장진흥공단 (2026-08-14 수정). 전국 상호명, 업종, 주소, 위도·경도. 무료, 현재 이용허락범위 제한 없음(표시된 범위 기준). 공공데이터의 이용가능 여부는 매장 영업 상태/주력 품목/재고를 보증하지 않는다.
- API 작업 명세: `GET /B553077/api/open/sdsc2/storeListInRadius` (반경 내 상가업소 조회, **상권 폴리곤 `storeZoneInRadius`와 다름**).
- 필수 변수: `serviceKey`(서버 전용), `cx`=경도, `cy`=위도, `radius`=미터, `type=json`.
- 중심 반경 요청은 최대 2,000m만 실행하며, 최대 1,000건씩 **3페이지(최대 중심 원자료 3,000건)**까지 조건부로 검사. **사용자가 3·5·10km를 선택하면 중심 조회 후 동·서·남·북 최대 네 방향을 각각 2km 반경/첫 페이지만 추가 샘플링**해 주변 후보를 보강한다(중심 3회+외곽 4회=요청당 최대 7회). 외곽 요청 실패는 중심 결과를 보존하고 재시도 캐시는 30초로 단축한다. 공공데이터 요청 전체가 11.5초 안에 끝나도록 통합 시간 제한을 적용한다. 남은 페이지가 있거나 사용자 검색반경이 2km를 넘으면 **방향 보강에 성공했더라도** `coverageLimited:true`다. 동서남북의 2km 원 네 개는 전체 반경을 빠짐없이 덮지 못하고 각 원의 첫 페이지만 살펴보기 때문이다. 반환 매장 후보는 최대 250곳이고 중복 상가ID는 병합함. **검색된 0곳을 전국에 0곳 있다고 해석하지 않음.**
- 데이터 갱신시각(기준년월 `stdrYm`)은 정부 원문에 있는 경우에만 반환.
- 정부 상가업소번호(`bizesId`)와 공식 판매처 내부 지점코드를 동일하다고 간주하지 않음.
- 서버는 매장 브랜드가 CU/GS25/세븐일레븐/이마트24/이마트/트레이더스/롯데마트/홈플러스/코스트코/하나로마트로 **명확히 시작하는 상호명**만 후보로 출력. 이 확인은 곧 *매장이 실제로 그 회사의 운영점인지* 또는 *포켓몬 카드를 취급하는지* 확정하는 절차가 아님.
- 최초 조회에도 자동 Firestore 저장/재고 기록은 없음. 수동 검증된 지점만 기존 `import-verified-stores.mjs`로 저장 가능.

## 운영 설정

1. https://www.data.go.kr/data/15012005/openapi.do 에서 **활용신청**하고 일반 인증키 발급. 서비스 이용조건과 호출 한도를 확인.
2. Vercel `digital-card-radar-api` 프로젝트의 Production 환경변수에 **`RADAR_GOV_BUSINESS_API_KEY`** = 발급한 서비스키 설정. 민감 데이터는 GitHub, 브라우저, 채팅에 입력하지 않는다.
3. Vercel Production 재배포. 라이브 환경에서 `GET /api/v1/public-shops?lat=37.39&lng=127.11&radiusKm=2`를 열어 `status:"ok"` 및 후보값을 검증. API를 호출하지 못하면 `status:"unavailable"`이 반환되고 기존 레이더 검색은 유지된다. 브라우저에는 원본 키가 반환되지 않는다.
4. 레이더에서 지정 지역 탐색. 기존 독립 Firestore 마스터·OSM 후보와 정부 후보를 중복 병합하되 재고 없음/재고 미확인을 구분한다.

API 키를 등록하지 않았다면 `status:"not_configured"` (HTTP 200)가 반환되며, 페이지에는 **'정부 상가 위치 보강 API 키 등록 전'** 메시지가 표시된다. 즉 코드 배포만으로 정부 자료가 전국 지도에 나타나는 것은 아니다.

## 기술·정책상 유의점

- OSM 정보는 화면 실시간 후보 조회에 사용하되, 정부 공공데이터 API 결과를 자체 Firebase의 검증 매장으로 자동 저장하거나 OSM 기반 좌표를 무분별하게 섞지 않는다. 별도 출처/ODbL 준수 확인 필요.
- 매장 후보는 재고 상품을 보유하지 않고 `verifiedInventory:[]` 및 `stockStatus:unknown`이며, 자체 DB의 검증된 매장과 달리 `locationStatus:candidate` 상태다.
- API의 서비스키는 서버에서만 읽고, 예외 로그나 응답 내용에 출력하지 않는다.
- 단일 지역 검색당 정부 API **2km 이하 최대 3회 / 2km 초과 최대 7회** 요청(필요 없으면 일찍 종료). 지역·판매처별 10분 메모리 캐시 사용. 지역·브랜드 및 페이지에 따라 API 호출량이 증가할 수 있으므로 제공처 일일 할당량을 모니터링해야 함. 페이지2~3 오류 시 페이지1 후보는 보존하되 `coverageLimited:true` 표기. 외곽 4개 샘플은 **병렬 첫 페이지 요청만** 허용하며, 실재고로 저장하지 않는다. 공공데이터 호출 할당량이 빠르게 소진될 수 있으므로 사용량을 확인해야 한다.
- 중심 응답 `pagesFetched`, `sourceRowsExamined`, `sourceTotalCount`는 중심 조회에만 해당하며, 외곽 보강은 `supplementalCentersAttempted`, `supplementalCentersFetched`, `supplementalRowsExamined`로 따로 기록한다. 응답 `sourceYearMonth`는 실제 조회와 원문 기준 시점을 분명히 알리기 위한 메타데이터. `sourceYearMonth`가 오래된 데이터면 현재 매장이 영업 중이라고 단정하지 않음.
- 공공데이터의 사용권한과 CU·GS25 등 각 판매처 실시간 재고를 재배포할 권한은 **전혀 다른 것**이다. 정부 상가 정보의 공개 여부가 판매처별 재고 연동 허가를 의미하지 않는다.
