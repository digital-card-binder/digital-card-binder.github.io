# 카드레이더 — 공개 재고 데이터 조회 방식 조사 (2026-10-19)

## 목적과 판정

도감앱의 '카드샵 지도 > 장소/재고'를 기능 기준으로 참고한다. **다른 서비스의 비공개 API, 인증 정보 또는 재고 데이터를 복제하지 않는다.** 앱 내 1종/5종 표시가 실제로 정확하다면, 차이는 지도 UI뿐 아니라 **상품코드·매장코드·판매처별 조회 방식**에서 나올 수 있다.

- 확인된 공개 사실: 도감앱 운영자가 2026-10-14 게시물에서 이마트·롯데마트 등 마트 및 편의점 재고를 볼 수 있으며 편의점·마트 앱의 재고 수치와 대체로 일치한다고 설명했다. 판매 후 전산 반영 지연은 남는다.
- **미확인 사실**: 도감앱의 내부 서버, 공급처 API, SKU/점포코드 DB, 인증 방식, 캐시 TTL, 제휴·재배포 사용 허가. 앱 표시의 정확도를 사용자 경험과 운영진 설명 외에 독립 검증하지 않았다. 비공개 API를 추측해 연결하지 않는다.
- 공개 매장 페이지에 경기 지역 편의점 13,526곳이 나타난다고 해서 실재고가 있는 13,526곳을 의미하지 않는다. 점포 디렉터리와 상품별 재고 관측을 별개의 자료로 구분한다.

## 공개 코드에서 검증된 상품·매장 중심 처리

Daiso MCP는 공개된 오픈소스 집계 서비스이며, 각 판매처와 독립된 **제3자 연동**이다. 이 서비스를 호출한다고 각 리테일러가 카드레이더의 대량 재배포를 승인한 것은 아니다.

1. **상품 실체 확인** — 판매처별 상품 검색을 통해 해당 카드팩의 상품코드(바코드/PLU 등)를 찾고, 상품명/판매단위(낱팩·박스)까지 비교한다. 이름만 비슷한 첫 후보로 결정하지 않는다.
2. **정확한 점포 집합** — 서비스가 반환한 판매처 점포코드에 위경도/주소를 연결한다. 단순 좌표 0.1km 내 이름 유사 매장이 동일 점포라고 단정하지 않는다.
3. **점포×상품 재고** — 확인된 `(retailerId, storeCode, productCode)` 조합에 한해 수량을 조회한다. 서비스마다 검색어만 지원하거나 수량 응답이 없는 경우도 있다.
4. **관측의 출처와 시각** — 조회 성공시각과 공급처에서 확인된 재고 관측시각을 별도로 저장한다. 두 값을 혼동하지 않는다.
5. **결과 상태** — 확인된 양수/정확한 0/수량 미확인/오래된 관측/지원 불가/호출 오류를 분리한다. 재고 정보가 없다고 0개를 생성하지 않는다.

특히 이마트24 공개 구현 `src/services/emart24/inventoryLookup.ts`은 다음 흐름을 실행한다.

```text
입력 상품명 또는 명시 PLU
→ 상품 검색 및 PLU 선택 (정확히 일치하면 우선, 아니면 첫 후보를 선택할 수도 있음)
→ 이마트24 점포 코드(bizNo) 목록 선정
→ PLU × bizNo를 이용한 점포별 수량 조회
→ 응답 매장과 수량을 합침
```

**위험 지점:** 해당 공개 구현은 사용자가 상품코드를 전달하지 않을 때 이름이 정확히 일치하지 않으면 첫 검색 후보를 고르는 fallback이 있다. 또 사용자가 점포코드/매장 키워드를 전달하지 않으면 기본 매장 목록의 첫 페이지에서만 가까운 점포를 골라 조회하므로, 선택 위치와 먼 도시의 후보에 국한될 수 있다. 코드상 파라미터 `latitude/longitude`는 결과를 정렬하지만 원천 점포 디렉터리 전체를 지리 반경으로 검색한다는 보장은 없다. **따라서 단순 `keyword+lat/lng`만 전달하는 카드레이더는 반경 전체의 재고를 보장할 수 없다.**

다른 브랜드의 현재 지원범위도 동일하지 않다. PokeConv 공개 방법론에는 CU/세븐일레븐의 원본 재고 수량 누락, 이마트24 연결 제한과 이전 관측, GS25의 30주년 한정 확인 등이 명시된다. 제3자 보고일 뿐 다른 앱 내부 구현 근거는 아니다.

## 동일 정확도에 가까워지기 위한 우선 구현 (별도 후속 PR)

1. **P0 상품 대응표:** `retailerId, canonicalSetId, retailerSku, itemName, packUnit, verifiedAt, evidence` 구조. 검증된 상품코드만 수량 확정; 검색어의 첫 후보 자동 선택을 허용하지 않음. 처음에는 30주년 및 현재 신상품부터 시작.
2. **P0 점포 대응표:** `retailerId, retailerStoreId, normalizedName, lat, lng, source, verifiedAt`; 매장 API에서 반환하는 실제 코드와 매칭. 코드가 없는 공개지도 후보는 계속 '재고 미확인'.
3. **P1 리테일러별 연결기:** 출처별 권한이 있는 재고 피드만 서버에서 처리. 쿼터, 유효시간, 오류재시도/서킷브레이커; 선택 영역의 실제 점포코드에 한해 조회.
4. **P1 3상태 이상의 관측 저장:** `positive/zero/unknown/stale/unavailable` 및 원본 `observedAt`, 요청 `fetchedAt`, 상품단위, 공급원 식별. 실제 방문 전 재확인 안내 유지.
5. **P2 실사용 교차검증:** 동일한 매장×상품 20~50쌍을 각 브랜드 공식 앱과 카드레이더에서 동일 시각에 비교해 일치율, 미조회율, 최대 지연을 기록. 앱을 통한 수동 비교는 사용자/운영자 동의 하에 수행.
6. **P2 지도:** 실제 양수 관측 매장만 빨간 상품종수 마커, 미확인 매장과 품절을 분리. 모바일 우선 지도는 `PR #230`에 반영 예정.

## 하지 않을 일

- 다른 서비스의 내부 인증·쿠키·비공개 API를 무단 재사용하거나 서버 구현을 추측하는 일
- 재고 지원을 위해 일반 마트나 카드샵 위치 후보에 수량을 채우는 일
- 실제 공식 점포 재고라고 주장하면서 제3자 검색 결과의 수집시간을 원본 관측시간으로 속이는 일
- 출시 시점·전국 커버리지·마켓별 상품별 인증이 없는 상태에서 '모든 카드팩 실시간 조회 완료'라고 표시하는 일
