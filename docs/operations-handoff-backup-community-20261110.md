# 디지털 카드 바인더 — 운영 전환 확인 (2026-11-10)

## 운영 기준

- 개발/배포 기준: 최신 `main` 및 GitHub Pages 배포 성공. 회원 데이터는 GitHub 브랜치로 복구할 수 없음.
- 신규 대규모 기능 개발은 잠시 보류. 실사용 오류와 새 한국판 카드 발매 확인 시에만 수정.
- 타 채팅에서 진행한 커뮤니티 동기화 수정은 보존한다. 이 변경은 **공개 데이터 조회만** 테스트하며 기존 동기화/권한 로직은 바꾸지 않는다.

## 사용자 본인이 실행해야 하는 실제 백업

1. 관리자 계정으로 <https://digital-card-binder.github.io/operations.html> 로그인.
2. **백업 파일 만들기** 클릭. 브라우저 다운로드 목록에 JSON 파일이 실제 저장됐는지 확인.
3. 같은 운영센터의 **백업 파일 검증 및 복구**에서 방금 받은 JSON 파일을 선택. ‘백업 파일 검사 통과(읽기 전용)’ 메시지 확인.
4. **‘선택한 백업 복구’ 버튼은 누르지 않는다.** 실제 복구는 기존 보유 기록을 변경하므로 사용자 별도 승인 시에만 수행.
5. 백업 파일은 로컬 드라이브 및 비공개 보관처에 보관. GitHub 공개 저장소·채팅·이슈에 업로드하지 않음.

이 단계는 사용자 계정에서만 가능한 작업이다. 자동 GitHub Actions에는 관리자 로그인이나 Firestore 사설 문서 읽기 권한이 없다. 자동 점검 성공과 실제 백업 파일 생성은 서로 다른 상태이며, 파일 다운로드 자체도 자동으로 확인할 수 없다.

## 자동 점검

새 GitHub Actions `Production Community & Backup Readiness (read-only)`가 매일 **09:30 KST**에 공개 사이트 주요 화면과 배포 JS 및 Firestore의 **익명 읽기 가능한 공개 커뮤니티 컬렉션**을 제한된 수량만 검사한다. 사용자가 공개 설정한 프로필만 읽으며, 계정 UID/이메일/닉네임/카드 개별 기록을 로그에 남기지 않는다.

- 공개 사이트 HTML·JS 파일 존재 및 전송: 실제 배포 상태
- 공개 디렉터리 조회 및 대표 공개 프로필·도감 projection: **익명 읽기 경로** 기본 동작
- 전수 게시글 최신 반영, 소유자→공개 Firestore 동기화 쓰기, 비공개 데이터 또는 로그인 세션: **이 작업에서 검증 불가**
- `reports/public-service-smoke.json` 아티팩트: 오류 코드·검사 개수만 기록, 14일 보관
- 검증 실패 시 작업이 빨간색으로 표시되며 자동 수정·Firestore 쓰기는 하지 않음
- 날짜 기준 자동 테스트는 CI 실행 시점에 수행되고, 실제 브라우저 환경과 기기별 UX는 사용자 확인 필요

## 수동 실사용 확인

커뮤니티 관련 작업이 모두 배포된 다음, 실제 회원 두 명의 동의하에 다음 순서로 확인한다. 소유자 계정이 테스트 카드 1장의 보유 상태를 변경하여 저장 성공 메시지를 확인하고, **다른 브라우저나 비로그인 화면**에서 해당 회원의 공개 도감에 최신 상태가 표시되는지 확인한다. 비공개 전환 시 해당 도감이 일반 방문자에게 보이지 않는지 확인한다. 변경한 테스트 카드는 원래 상태로 되돌린다.

백업 파일을 만들고, 공개 도감 동기화까지 2계정으로 확인한 뒤에는 신규 차수 개발 대신 사용 중 발견된 버그만 재현·수정한다. 월 1회 및 큰 변경 전 백업을 권장한다.
